# 03: Push to existing encrypted local-storage records

**Source:** [Save files to a provider](../../specs/03-save-files-to-provider.md)

**What to build:** Save exact local edits into the existing encrypted records selected by managed-file references, sharing the approved push workflow while preserving unrelated ciphertext and independent manual updates.

**Blocked by:** [02: Push managed files to manual configuration values](02-push-manual-values.md)

**Status:** blocked

- [ ] Resolve qualified and unqualified references under existing local-storage rules to an existing `(ID, public key)` target using exactly one matching eligible SSH-agent key/record. Qualified references restrict the key; unqualified references require one unambiguous match. Missing records/keys, ambiguity, ineligible keys, agent failures, and integrity errors fail affected targets. Never create a record or offer alternate-key selection.
- [ ] Compare exact decrypted raw values, including empty/whitespace text, not normalized fetch results. Group by resolved target rather than reference spelling: identical local contents coalesce into one update; differing contents fail the entire target, even if one input matches its current value. Unrelated targets continue. Report all files represented by each target and show applicable shared-reference warnings before approval without revealing contents.
- [ ] Enforce the 1,048,576-byte provider limit and existing encoded-format bounds, retaining the shared 4 MiB input and 64 MiB pre-deduplication aggregate policy. Bound provider plaintext buffers and zeroize their owned lifetimes; do not stage plaintext, expose it in argv/diagnostics, or introduce a persistent cache.
- [ ] Immediately before persistence, revalidate every participating input and reload latest source/configuration state. Verify mappings still resolve to approved targets with eligible keys and existing valid records. Changed source values alone are authorized overwrites, not stale-source conflicts; removed, retargeted, newly ambiguous, or unsafe targets fail. Preserve unrelated IDs, newly added records, and other keys' storage.
- [ ] Retain direct configuration-relative `.psst/` storage, existing cryptography/format, private-path permissions, integrity checks, cooperative locks, atomic replacement, and loaded-content checks between latest reload and persistence, including the final post-sign race check. Adapt existing authoring responsibilities only as needed; its creation and stale-snapshot behavior cannot substitute unchanged for push semantics. Preserve existing TUI authoring/fetch/deletion behavior.
- [ ] Integrate independent best-effort results with manual saves, including completed encrypted writes surviving a failed configuration save. Distinguish failure before replacement from changed ciphertext with uncertain durability; any failure/cancellation is nonzero. Cancellation of queued/active agent work releases owned sockets/locks/buffers without retry/fallback or undoing completed writes.
- [ ] Add isolated binary acceptance tests using the shared deterministic fake Unix agent for exact text, raw unchanged detection, qualified/unqualified aliases, identical coalescing, conflicting inputs, per-file reports, provider size boundaries, latest-value overwrites, unrelated data preservation, and direct configuration-relative storage from another working directory. Ordinary tests must not inherit personal agents or invoke real providers.
- [ ] Add focused tests for missing/sole/multiple/ineligible identities and records, refusal, timeout, cancellation, integrity/format errors, no creation/alternate-key fallback, changes to inputs/mappings/target eligibility after planning, lock contention, final conflicts, and injected pre/postreplacement evidence. Retain crypto/format, permission, atomicity, agent serialization/deadline, and authoring regressions; record evidence and inspect zeroizing ownership. Keep local storage experimental and preserve inherited release gates rather than treating fake-agent success as independent crypto review.
