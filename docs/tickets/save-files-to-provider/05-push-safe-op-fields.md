# 05: Push to safely round-trippable existing 1Password fields

**Source:** [Save files to a provider](../../specs/03-save-files-to-provider.md)

**What to build:** Extend the approved push workflow to existing text/concealed `op` fields only where safe item round-trip eligibility can be established, preserving unrelated latest item data and reporting remote uncertainty honestly.

**Blocked by:** [02: Push managed files to manual configuration values](02-push-manual-values.md); [04: Support bounded exact subprocess transfers without changing fetch behavior](04-bounded-exact-subprocess-transfers.md)

**Status:** blocked

- [ ] Resolve an unambiguous existing vault/item/field identity before grouping; textual reference equality is insufficient. Compare exact raw field values rather than trimmed `op` fetch output. Omit unchanged targets from approval and writes, coalesce identical inputs for one resolved target, and fail all files sharing a target with differing inputs. Independently valid targets continue.
- [ ] Fail closed unless safe item round-trip eligibility is established. Accept only existing text/concealed fields within that eligibility; reject passkey-bearing items, attachments, derived OTP targets, SSH-key/unsupported items, ambiguous or missing targets, and item/field creation. General CLI editing support and a permissive fake executable are not evidence that arbitrary items are safe. Keep the eligibility mechanism and internal types implementation-owned within these restrictions.
- [ ] Respect the shared exact UTF-8, NUL, per-file, pre-deduplication aggregate, input-path, and memory-only planning rules, and enforce stricter provider limits. Bound raw item/list/output and serialized payload buffers, including unrelated item data; retain zeroizing ownership for secret-bearing working state. Never put payloads in argv, diagnostics, or temporary files.
- [ ] Immediately before item persistence, revalidate every participating local input and reload latest configuration/source state. Confirm approved mappings still identify intended existing eligible targets. Latest field-value changes are approved overwrites, not stale-value conflicts. Removed/retargeted/newly unsafe targets fail while unrelated valid work continues. Safely combine approved different-field updates in one item from latest state, preserving unrelated fields and metadata.
- [ ] Send secret-bearing edit payloads over stdin using bounded cancellable subprocess work. Preserve the existing authentication/read behavior outside push. A final reread does not guarantee conditional writes: retain and document `op`'s remote race rather than claiming race exclusion or transactions.
- [ ] Integrate into the single content-free batch confirmation with paths/providers/shared-reference warnings and `--yes` safety semantics. Report every represented file and independent item/group result; failures are nonzero. Failed or interrupted remote edits must not be reported as definitely saved or rolled back when the outcome is uncertain. Retain completed writes on cancellation and do not roll back other providers.
- [ ] Use fake `op` at the binary boundary to verify exact empty/whitespace/multiline/Unicode field values, raw unchanged detection despite normalized pull, aliases coalescing, conflicting inputs, multiple approved fields per item, latest-source overwrite, unrelated/latest metadata preservation, and removed/retargeted targets. Verify stdin equality, secret-free argv/errors, bounded working data and provider-limit failures, no staging, and every grouped file's outcome.
- [ ] Exercise all fail-closed exclusions, ambiguous vault/item/field names, unsupported/unknown sources, shell and derived `op 2FA` without reverse command execution, newly unsafe latest items, changed local inputs, failed edits, timeouts, and cancellation before/during writes. Assert partial and uncertain outcomes and cleanup; preserve existing trimmed/empty-read fetch behavior with focused regressions.
- [ ] Record the eligibility rationale and compatibility evidence without claiming live verification from fixtures alone. Real-provider checks require explicit opt-in and isolated nonpersonal fixtures; support claims must not exceed established safe eligibility. Ticket 07 records final cross-platform and real-provider release evidence or outstanding gates.
