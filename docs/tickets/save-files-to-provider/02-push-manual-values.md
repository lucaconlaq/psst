# 02: Push managed files to manual configuration values

**Source:** [Save files to a provider](../../specs/03-save-files-to-provider.md)

**What to build:** Provide a complete `psst --files-push [--yes]` path that safely snapshots configured managed files, obtains one approval, and updates manual literals together while reporting individual outcomes. Establish the shared push workflow for subsequent writable providers without importing pull's disk staging.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Push selects all configured managed files in configuration order, never environment entries. Empty sets succeed with guidance. Explain local → provider direction in help and usage; reject push with pull (including the legacy alias), copy, environment export, or wrapped-command execution. Preserve arguments after command dispatch or `--` and unrelated CLI/TUI behavior. Remain independently landable from ticket 01.
- [ ] Resolve literal paths beside the selected configuration, including absolute/outside-project paths. Missing/unreadable inputs fail individually. Refuse symlinked files or ancestors, nonregular files, and configuration/storage artifacts, including reachable aliases. Read regular inputs without requiring mode 0600; do not change their bytes or permissions.
- [ ] Preserve exact UTF-8, including empty text, Unicode, whitespace, and newlines. Reject invalid UTF-8, NUL, and files above 4,194,304 bytes. Retain planned local plaintext only in zeroizing memory; cap its aggregate at 67,108,864 bytes before deduplication. Over-cap aborts the batch before any source writes; no plaintext staging or disk fallback. Bound working buffers and respect the existing persisted configuration size limit. Intended manual-literal JSON persistence is permitted.
- [ ] Compare manual literals as raw stored values. Unchanged files require neither approval nor persistence; an entirely unchanged batch does not prompt. Unsupported sources fail individually without executing shell commands or preventing valid manual saves. Local-storage and `op` become writable in their later tickets; do not claim their support here.
- [ ] Before any source changes, present one content-free batch summary identifying affected paths, providers, and applicable shared-reference warnings. Interactive approval defaults to no; refusal/unavailable consent produces no source writes and nonzero status. `--yes` supplies approval without bypassing safety. Warn conservatively rather than claiming complete reference discovery across configurations.
- [ ] Immediately before persistence, revalidate each participating input's identity, original path safety, and exact contents. Fail changed targets without saving stale or reread contents; continue unrelated valid work. Reload latest configuration and verify each approved mapping still identifies the intended manual target. Overwrite latest literal values even if changed since planning, preserve environment entries and unrelated/added mappings, and reject removed, retargeted, or newly unsafe targets.
- [ ] Commit all valid approved manual-file updates in one atomic configuration save. Retain cooperative locking and loaded-content checks from the latest reload through persistence; final races/lock contention may fail rather than clobber another writer. Report pre-replacement failure separately from replacement with uncertain durability, attributing the grouped result to every affected file.
- [ ] Report every configured managed file as saved, unchanged, or failed with content-free diagnostics; any failure, refusal, or cancellation is nonzero. Cancellation discards owned plaintext and unfinished work, retaining completed writes and truthful partial outcomes. Do not introduce subset selection, arbitrary import, automatic write-back, TUI saving, dry-run, JSON output, or watch behavior.
- [ ] Use isolated binary/terminal acceptance tests for empty/no-change/mixed batches, default refusal, interactive approval, unattended approval, one summary, per-file results, and incompatible modes. Cover exact text and input/cap boundaries, aggregate counting before deduplication, another working directory, absolute/outside paths, nonprivate inputs, missing/unsafe paths, protected aliases, and unchanged input bytes/permissions. Assert over-cap/refusal runs perform no source writes and create no plaintext staging.
- [ ] Use existing persistence seams and, only where necessary, internal controllable plan-to-persist boundaries for input identity/ancestor/content/safety races, latest-value overwrite, unrelated mapping preservation, removed/retargeted targets, final conflicts, lock contention, cancellation, and pre/postreplacement failures. Inspect diagnostics/artifacts and zeroizing ownership, not filesystem cleanup alone. Internal types and test seams remain implementation-owned, not public API decisions; record test evidence.
