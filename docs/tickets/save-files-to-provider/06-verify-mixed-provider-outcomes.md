# 06: Verify mixed-provider partial completion and interruption

**Source:** [Save files to a provider](../../specs/03-save-files-to-provider.md)

**What to build:** Prove, and fix where necessary, that a single multi-provider push retains independent valid updates and reports complete, truthful per-file results through conflicts, grouped failures, and interruption. Provider-specific success and safety coverage must already land with its owning ticket.

**Blocked by:** [03: Push to existing encrypted local-storage records](03-push-encrypted-records.md); [05: Push to safely round-trippable existing 1Password fields](05-push-safe-op-fields.md)

**Status:** blocked

- [ ] Exercise a mixed configuration of environment entries and manual/local-storage/eligible `op` managed files alongside missing, unchanged, conflicting-shared-target, and unsupported files. Verify one content-free approval before all source writes, no prompt if nothing changes, no writes on refusal/unavailable consent, `--yes` without safety bypass, empty-set success, and no environment entry updates.
- [ ] Verify every configured managed file is reported as saved, unchanged, or failed, including every file behind coalesced targets, combined item edits, and the atomic manual group. Unsupported/missing targets remain failures in no-change runs. Any failure/refusal/cancellation is nonzero; partial completion is explicit without cross-provider rollback.
- [ ] Force manual configuration-save failure independently of completed encrypted/remote writes. Cover pre-replacement failure and replacement with uncertain durability, surviving source state, and attribution to the manual group. Combine provider failures in different orders without allowing one independent failure to discard valid later work.
- [ ] Inject input identity/ancestor/path-safety/content changes and source-value/unrelated-data mutations across planning and persistence. Verify intended latest-target overwrite, unrelated data preservation, failure of removed/retargeted/newly unsafe targets, target-wide failure for changed shared inputs, and retained local conflicts/lock checks. Reuse existing persistence and fake-agent seams; add internal controllable boundaries only where necessary, without defining public APIs.
- [ ] Interrupt before writes, between persistence groups, and during agent/subprocess work. Verify owned buffers, sockets, locks, and subprocess work are cleaned up, completed writes remain, and reports distinguish definite failure, uncertain local durability, and potentially uncertain remote outcomes. No cancellation path may silently claim all work rolled back or definitely saved.
- [ ] Inspect captured argv, stdout/stderr, and temporary artifacts across success, refusal, cap failure, provider failure, and cancellation for unintended plaintext. Assert no plaintext push staging, no input byte/permission changes, and no shell execution for unsupported reverse operations. Review/focus-test zeroizing ownership lifetimes and bounded provider buffers; filesystem assertions alone are insufficient evidence of memory cleanup.
- [ ] Use isolated CLI tests with fake `op` and the shared deterministic fake agent plus representative terminal approval/cancellation tests. Include aggregate-cap-before-deduplication coverage across providers, proving abort before writes. Record acceptance/fault-injection evidence and any fixes; ordinary runs must not inherit personal agents or authenticate to real providers.
